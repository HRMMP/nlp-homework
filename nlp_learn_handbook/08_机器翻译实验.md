# 08. 机器翻译实验

本章把前面学到的概念映射到本项目的机器翻译任务。具体数据集、语言方向、模型规模和训练轮数尚未由本手册预先确定，实施时必须在配置和报告中写明。

## 1. 先定义问题

机器翻译是序列到序列任务：给定源语言句子，生成目标语言句子。

需要在实验开始前确认：

- 源语言和目标语言是什么。
- 数据集名称、来源、许可证和划分方式。
- 一条样本是怎样的字段结构。
- 是按字、词还是子词 token 化。
- 两种语言是否分别使用词表。
- `<pad>`、`<bos>`、`<eos>`、`<unk>` 的 id。

不要因为“机器翻译通常这样做”就替实际方案作答。实验报告的这些字段必须来自真实配置。

## 2. 数据流

```text
源句 -> 源 tokenizer -> source_ids
目标句 -> 目标 tokenizer -> target_ids
source_ids + source_padding_mask
      -> Encoder
目标前缀 + target causal mask
      -> Decoder 读取 Encoder 输出
      -> logits
      -> greedy/beam decoding
      -> 去除特殊 token
      -> BLEU 和错误分析
```

训练时目标序列错开一位：

```text
target: <bos> 我 喜欢 猫 <eos>
input:  <bos> 我 喜欢 猫
label:      我 喜欢 猫 <eos>
```

## 3. Transformer 组件

报告和代码说明至少覆盖：

- token embedding。
- 位置编码或位置 embedding。
- Encoder self-attention。
- Decoder causal self-attention。
- Decoder cross-attention。
- FFN、残差连接和 LayerNorm。
- 线性输出层和交叉熵。
- padding mask 与 causal mask。

你可以自己实现核心模块，也可以使用成熟库；但无论哪种方式，都必须能解释实际调用的组件和张量形状。

## 4. 训练前的最小验证

### 4.1 数据检查

打印几条：

- 原始源句和目标句。
- token 列表和 token id。
- padding 后长度。
- Decoder 输入和 label 的对应位置。
- mask 中可见和不可见的位置。

### 4.2 形状检查

至少检查：

```text
source_ids: (B, source_length)
target_ids: (B, target_length)
logits:     (B, target_length, target_vocab_size)
```

### 4.3 极小数据过拟合

只使用极少样本，确认模型可以降低训练损失并生成接近训练目标的输出。它不是正式结果，只用于排查：

- 标签错位。
- mask 方向错误。
- padding 没有忽略。
- tokenizer 或词表映射错误。
- 优化器没有更新参数。

## 5. 推理方式

- **Greedy decoding**：每一步选择最高概率 token，简单但不保证整句最优。
- **Beam search**：保留多个候选前缀，需要处理累计分数、长度偏置、结束条件和 beam size。

必须记录：解码方式、最大生成长度、长度惩罚、是否去掉特殊 token，以及模型使用的 checkpoint。

## 6. BLEU 和报告写法

BLEU 不是“翻译是否正确”的唯一答案。报告至少应说明：

- BLEU 实现和版本。
- 最大 n-gram 阶数。
- 参考译文数量。
- tokenization 和大小写处理。
- 平滑方法。
- 在哪个划分上计算。

不同配置下的 BLEU 不能直接比较。还要保存若干真实的源句、参考译文和模型译文，分析漏译、错译、重复、专有名词错误和长句错误等现象。

## 7. 评估文件建议

每条预测至少保存：

```json
{
  "source": "源句",
  "reference": "参考译文",
  "prediction": "模型译文"
}
```

评估脚本应能从这个文件独立重算 BLEU。这样即使你更换报告格式，也不会丢失原始证据。

## 8. 学习任务

1. 手工写出一条样本的 source ids、target decoder input 和 target labels。
2. 画出 Encoder、Decoder self-attention 和 cross-attention 的数据来源。
3. 为目标序列写出 causal mask 的可见区域。
4. 设计 10 条样本的过拟合测试。
5. 选择几条真实预测，按错误类型而不是按“感觉不好”分析。

## 10. 实验完成标准

在声称实验完成前，应有：数据和配置、训练日志、验证 checkpoint、测试预测文件、独立 BLEU 评估、若干错误样例，以及对数据和模型局限的说明。没有这些记录时，只能说“已完成代码阅读或 smoke test”，不能说已经得到正式翻译结果。
