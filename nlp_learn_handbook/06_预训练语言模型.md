# 06. 预训练语言模型：BERT 与 GPT

## 1. 为什么需要预训练

如果每个下游任务都从随机参数开始，模型需要大量标注数据才能学到语言规律。预训练先利用大量文本学习通用表示，再用较小的任务数据进行微调。

基本分工是：

```text
预训练：学习一般语言规律
微调：学习具体任务的输入输出关系
推理：在新样本上产生预测
```

预训练不保证模型理解所有事实，也不保证下游任务一定成功。数据质量、领域差异、标签质量和评估规则都会影响结果。

## 2. BERT：双向 Encoder 表示

BERT 使用 Transformer Encoder。对某个位置的表示，self-attention 可以读取上下文中前后的有效 token，因此适合理解整句文本。

BERT 的输入通常包括：

```text
token embedding + position embedding + segment embedding
```

单句 NER 中 segment id 通常相同。输入还要配合 attention mask 区分真实 token 和 padding。

对于长度为 `L` 的输入，BERT 输出：

```text
last_hidden_state.shape = (B, L, H)
```

NER 可以在每个位置接一个线性分类头：

```text
logits.shape = (B, L, C)
```

这里 `C` 是 BIO/BIOES 标签数量，而不是 BERT 词表大小。

## 3. BERT 的预训练任务

原始 BERT 论文介绍了两个预训练目标：

### 3.1 Masked Language Model, MLM

随机选择一部分 token，让模型根据双向上下文预测被选择的 token。它类似完形填空，但训练实现会对被选位置采用特定的替换策略。学习时应以实际模型和论文版本为准，不要把某个教程中的比例当成所有模型的固定规则。

### 3.2 Next Sentence Prediction, NSP

给模型两个句子，让它判断第二个句子是否是第一个句子的后续。后续模型和研究对 NSP 的使用方式并不完全相同，因此介绍 BERT 时要区分“原始 BERT 的设计”和“所有 Encoder 模型的共同属性”。

## 4. BERT 做 NER 的微调流程

```text
原始句子和词级标签
  -> tokenizer
  -> subword 与标签对齐
  -> BERT Encoder
  -> 每个位置的分类头
  -> 过滤特殊 token/padding
  -> BIO 标签解析
  -> 实体级 P/R/F1
```

最重要的工程问题往往不是添加线性层，而是标签对齐。原始数据可能以词为单位，而 tokenizer 可能把一个词拆成多个 subword。需要明确：只给首 subword 计算损失，还是给后续 subword 分配 `I-X` 等标签，并保持评估规则一致。

## 5. GPT 类模型：自回归 Decoder

自回归语言模型按照下面的条件概率生成：

```text
P(x_t | x_1, ..., x_{t-1})
```

Decoder 的 causal self-attention 只能读取当前位置之前的 token。训练时可以并行计算每个位置的 next-token loss；推理时必须使用已经生成的前缀逐步预测。

典型生成流程：

```text
prompt
  -> 模型输出 logits
  -> 选择下一个 token
  -> 拼接到序列
  -> 重复，直到停止
```

常见解码设置包括 greedy、temperature、top-k、top-p 和最大新 token 数。任何正式比较都要固定或记录这些设置。

## 6. BERT 和 GPT 的主要差异

| 对比 | BERT | GPT 类模型 |
| --- | --- | --- |
| 主要结构 | Transformer Encoder | Decoder 风格的自回归 Transformer |
| 注意力 | 可看双向上下文，排除 padding | causal，只看前文 |
| 常见预训练目标 | MLM 等理解型目标 | next-token prediction |
| 常见下游方式 | 分类、NER、抽取 | 续写、问答、指令生成 |
| 典型输出 | 每个位置的 hidden state | 每个位置的下一个 token logits |

“BERT 双向、GPT 单向”是注意力可见范围和训练目标的简化概括。实际模型可能有更多结构差异，阅读具体模型文档时不能只靠这句口诀。

## 7. Prompt 和指令微调

Prompt 是把任务组织成模型输入的模板。例如数学任务可以包含题目、要求和答案格式：

```text
问题：{question}
请解题，并在最后写出最终答案。
回答：
```

Prompt 变化可能改变模型输出。训练和评估需要记录模板版本，并检查是否把参考答案或测试信息意外写入 prompt。

指令微调使用“指令/输入 -> 期望回答”的监督样本，使模型更倾向于遵循任务要求。它不等同于模型具备可靠的数学证明能力，生成解释也不等于答案判对。
