## 1. 建议做到什么程度

以根目录作业 PDF 为硬性要求，目标为“完整、可复现、能解释的课程实验”。PDF 要求 Transformer 翻译与 BLEU、BERT NER 与 P/R/F1、数学数据上的 LoRA 与测试准确率，没有指定必须达到的分数，也没有要求论文级创新、大规模模型或全面网格搜索。

以下验收标准是结合官方资料提出的本项目建议，不是老师额外布置的要求：

| 实验 | 建议完成标准 | 不作为本轮目标 |
|---|---|---|
| 翻译 | 固定版本的数据质量审计；切分前固定去重规则；一个清晰的 Transformer 配置；训练曲线；完整测试预测及 SacreBLEU 签名；5–10 个经学生核查的译例 | 追求某个通用 BLEU 阈值、更换大模型、全套架构消融 |
| NER | BIO/subword 对齐验证；明确 dev 与 test 用途；strict IOB2 实体级总体及 10 类 P/R/F1；边界、类别、漏检和未见实体分析 | 用 token accuracy 替代实体指标、把 dev 结果改名为 test、为接近官方成绩盲目换模型 |
| LoRA | 同模型同 prompt 同解码的未微调基线；参数冻结审计；严格格式指标与抽取规则敏感性；保留现有单因素学习率对照；核查代表性输出 | 强求微调后必须提升、事后换规则只挑较高分、继续用已看过的 test 选参 |

共同要求：配置、环境、数据版本与许可证、随机种子、日志和预测可追溯；评分可独立复算；局部功能有测试和 smoke；结果不佳也照实保留。多 seed 与置信区间是有价值的增强项，不作为无限扩展实验的理由。

## 2. Web 查证依据

查阅日期：2026-10-08。查阅的是在线官方仓库和固定版本数据卡，不是仅依赖搜索摘要。

1. [SacreBLEU 官方文档](https://github.com/mjpost/sacrebleu)：使用反分词文本，记录分词、大小写、平滑等签名；可补充 chrF，但不能用附加指标代替作业要求的 BLEU。不同测试集上的分数不能直接比较。
2. [OPUS Books 固定 revision 数据卡](https://huggingface.co/datasets/Helsinki-NLP/opus_books/blob/1f9f6191d0e91a3c539c2595e2fe48fc1420de9b/README.md)：存在自动句子对齐，部分原始文本经过人工审阅；不能据数据集名称保证每条语向和句对正确。许可允许个人、教学和研究使用，不代表获准商业使用或大量再分发。
3. [Transformers token classification 教程](https://huggingface.co/docs/transformers/tasks/token_classification)：用 `word_ids()` 对齐，特殊 token 和后续 subword 置为 `-100`，使用实体级评价。
4. [seqeval 官方文档](https://github.com/chakki-works/seqeval)：strict IOB2 与默认 conlleval 兼容模式行为不同，必须注明模式和 scheme。
5. [CLUENER2020 官方说明](https://github.com/CLUEbenchmark/CLUENER2020)：10 类实体、字符闭区间标注；其线上基线使用不同评测设置，不能把本地 dev micro F1 与线上结果直接等同。
6. [lm-evaluation-harness GSM8K 固定版本配置](https://github.com/EleutherAI/lm-evaluation-harness/blob/d6de81643928d653435c431bae19945d41d32520/lm_eval/tasks/gsm8k/gsm8k.yaml)：同时提供 strict-match 和 flexible-extract；该配置还有 5-shot、特定 prompt 和停止规则。仅借用其抽取正则不等于完成官方 harness 评测。
7. [PEFT 官方 Quicktour](https://huggingface.co/docs/peft/quicktour)：用 LoRA 配置声明目标模块，检查可训练参数范围，保存 adapter 并重新加载。

### 3.1 翻译

复用固定 revision、seed 42 和全量运行配置，从本地缓存恢复 114,376 / 6,354 / 6,355 条 train / validation / test。全部测试源句和参考句仍与导出预测逐条一致。

精确文本审计结果：

- train 内重复句对的额外出现次数为 540，validation 和 test 各为 7。
- train/test 共有 45 个不同的精确句对键；这些键在 test 中共出现 52 次。因此不是“45 条测试记录”或“52 个不同句对”。
- test 有 94 条记录的 source 在 train 中出现过；target 对应计数为 86。单侧相同并不自动证明整个句对泄漏。
- train/validation 共有 43 个精确句对键，validation/test 共有 12 个。
- source 与 target 完全相同的记录在三部分分别有 81 / 6 / 5 条。专名、数字等也可能相同，不能直接把这些记录全部定性为坏数据。

现有报告已列出反向语向及疑似语义错配，但本轮没有进行全语料语言识别或人工语义审计。精确重复计数也不能发现近重复、同一本书的邻近句子或全部错配。

```bash
CUDA_VISIBLE_DEVICES='' python reports/verify_results.py --audit-cached-mt
```

结构化结果：`reports/evidence/results.json` 的 `cached_translation_pair_audit.overlap`。

建议下一步：使用成熟语言识别工具筛查全语料，按预先固定规则处理不确定项；由学生复核固定随机样本和疑似错配；在切分前去重并按 source 分组，避免同源句跨集合。语言识别不能证明语义对齐，必须保留人工复核和抽样覆盖的限制。如没有书籍元数据，不声称完成按书籍隔离的评测。新数据版本须重新训练，保留旧运行，不能只删测试难例后当作原分数的提升。

### 3.3 LoRA：新的关键发现

对已有 1,319 题生成文本采用两种抽取口径，所有问题 ID、题目和参考答案逐条配对验证；未修改原始预测、严格评分或训练配置。

| 抽取口径 | 未微调基础模型 | LoRA |
|---|---:|---:|
| 现有严格规则：`####`，回退 `boxed` | 482/1,319 = 36.54% | 655/1,319 = 49.66% |
| 最后数字诊断：上游 flexible-extract 正则 + 项目数值比较器 | 857/1,319 = 64.97% | 656/1,319 = 49.73% |

第二行是事后敏感性诊断，不是官方 harness 成绩，不是纯数学能力的无偏测量，也不能替换第一行。它复用已有 chat/greedy 输出，而非上游 5-shot prompt 和完整 exact-match 流程。最后数字可能抓到中间值、尾注或标点；基线中有 408 题从严格判错变为诊断判对，也有 33 题反向变化，不能只统计有利变化。

该结果说明原来“准确率提高 13.12 个百分点”对抽取协议十分敏感，不能据此宣称数学推理能力改善；同时也不能仅凭最后数字诊断断言真实推理能力下降了某个固定幅度。无需为了报告好看而继续训练直到提升。

复算无需 GPU 或新依赖：

```bash

  --baseline lora_math_finetuning/outputs/baseline_test.jsonl \
  --lora lora_math_finetuning/outputs/lora_test.jsonl \
  --output reports/evidence/scoring_sensitivity.json
```

产物记录原始文件 SHA-256、上游固定 commit、正则和口径差异、两种规则的逐模型计数及配对汇总。原始文件不被覆盖。建议学生分别阅读“严格错/诊断对”和“严格对/诊断错”样本，排查格式、解析误判、生成截断与真正解题错误。现有 test 已查看，不再用于新一轮选参。
