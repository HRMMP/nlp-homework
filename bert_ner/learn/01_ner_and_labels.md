# 01. NER、BIO 标注和标签对齐

## 1. NER 是什么

命名实体识别（Named Entity Recognition，NER）要在句子中找出实体片段，并判断实体类别。例如：

```text
句子:  张三在北京大学学习。
实体:  张三 -> 人名
       北京大学 -> 组织/机构名（具体类别以数据集定义为准）
```

它不是判断整句话属于哪个类别，而是对序列中的位置进行标注。因此 NER 常被称为序列标注任务。

## 2. BIO 标注

BIO 用标签表达实体的边界：

- `B-X`：一个 X 类实体的开始位置。
- `I-X`：同一个 X 类实体内部的后续位置。
- `O`：不属于任何实体。

示例：

```text
词:    张    三    在    北京    大学    学习
标签: B-PER I-PER O     B-ORG   I-ORG O
```

如果数据集使用 BIOES，还会有：

- `E-X`：实体结束位置。
- `S-X`：只有一个位置的单词实体。

BIO 和 BIOES 不能混用。必须查看数据集标签说明，并在报告中写清楚。

## 3. 标签和实体是两种不同对象

模型通常预测每个 token 的标签，但最终指标常按完整实体计算。

```text
预测: B-ORG I-ORG O
真实: B-ORG I-ORG O
```

这是一个完整实体预测正确。若预测成 `B-ORG O O`，虽然有位置预测正确，但完整实体边界不一致，实体级评估可能判为错误。

因此要区分：

- token-level：逐位置比较标签。
- entity-level：把连续的 BIO 标签解析成实体区间和类别后再比较。

## 4. 为什么 subword 会产生对齐问题

原始数据可能按“词”提供标签，但 BERT tokenizer 可能把一个词拆开：

```text
原始词:  playing
subword: play ##ing
原始标签: B-THING
```

现在必须决定如何给两个 subword 分配标签。常见策略有：

1. 只给第一个 subword 计算损失，其余位置设为忽略标签。
2. 第一个 subword 使用 `B-X`，后续 subword 使用 `I-X`。
3. 将原始标签复制到所有 subword（需要确认评估脚本是否接受这种处理）。

没有绝对适用于所有数据的方案，但必须保持训练和评估的一致，并在报告中说明。使用 Hugging Face tokenizer 时，通常通过 `word_ids()` 找到每个 subword 对应的原始词索引。

## 5. 特殊 token 和 padding

BERT 输入通常包含 `[CLS]`、`[SEP]` 和 padding。这些位置没有原始实体标签：

```text
[CLS] 张三 在 北京 [SEP] [PAD]
```

它们应被标为忽略标签，常见实现会使用 `-100`，因为 PyTorch 的交叉熵可以通过 `ignore_index` 跳过这些位置。注意：实际使用的忽略值必须和 loss 配置一致。

## 6. 先手工做一条对齐表

实现 tokenizer 后，打印至少以下列：

| subword | 对应原始词索引 | 原始标签 | 训练标签 |
| --- | ---: | --- | --- |
| `[CLS]` | - | - | `-100` |
| `张` | 0 | `B-PER` | `B-PER` |
| `三` | 1 | `I-PER` | `I-PER` |
| `[SEP]` | - | - | `-100` |

如果这张表无法解释，训练结果通常也无法解释。

## 7. 最小自测

1. `B-ORG` 和 `I-ORG` 的边界含义是什么？
2. `O` 标签为什么可能很多，但不能因此只报告 token accuracy？
3. 一个原始词被拆成三个 subword 时，至少需要做出什么决定？
4. 为什么 `[CLS]` 和 `[SEP]` 不应该被当成普通实体位置？
5. 预测的实体边界错一个位置，实体级指标是否一定仍然正确？为什么？
