# 02. LoRA 与参数高效微调

## 1. 全量微调的问题

假设某个线性层是：

```text
y = W x
```

全量微调会直接更新矩阵 `W`。大模型的 `W` 很多、很大，保存优化器状态和梯度会消耗大量显存，也需要保存完整的新模型副本。

参数高效微调（PEFT）的想法是：基础模型保持冻结，只训练少量新增参数。

## 2. LoRA 的核心公式

LoRA 不直接更新原始矩阵 `W`，而是学习一个低秩增量：

```text
y = W x + (alpha / r) B A x
```

其中：

- `W`：预训练的原始权重，冻结。
- `A`、`B`：LoRA 新增的可训练矩阵。
- `r`：低秩 rank，控制适配器容量。
- `alpha`：缩放因子。
- `alpha / r`：通常用于控制增量更新的尺度。

如果原始矩阵是 `d_out x d_in`，全量更新需要 `d_out * d_in` 个参数；LoRA 大约只需要 `r * d_in + d_out * r` 个参数。当 `r` 远小于两个维度时，参数量明显减少。

## 3. 为什么可以冻结基础模型

预训练模型已经包含通用语言能力。LoRA 假设具体任务需要的权重变化可以用一个低秩更新近似。训练时基础模型负责提供能力，LoRA 负责学习“如何适应数学任务”。这不是说 LoRA 一定和全量微调效果相同，而是用更低的训练成本换取任务适配能力。

## 4. 关键配置

- `r`：rank 越大，适配器容量和可训练参数通常越多。
- `lora_alpha`：增量更新缩放。
- `lora_dropout`：LoRA 分支上的 dropout，影响正则化。
- `target_modules`：把 LoRA 注入哪些线性层，例如注意力中的 query/value 投影；具体名称依赖基础模型架构。
- bias 策略：是否训练 bias。

这些值不是通用答案。应通过配置文件保存，并在报告中记录实际使用值。

## 5. 最重要的检查：到底哪些参数在训练

配置完成后打印参数统计。你需要确认：

- 基础模型参数的 `requires_grad` 为 `False`。
- LoRA 参数的 `requires_grad` 为 `True`。
- 可训练参数数量远小于总参数数量。
- 保存的 checkpoint 主要是 adapter 参数，而不是误保存完整基础模型。

如果所有参数都在训练，实验就不是预期的 LoRA 参数高效微调。这个检查应当成为 smoke test 的一部分。

## 6. 训练和合并

LoRA 训练时通常把基础模型和 adapter 一起使用。部署或推理时可以保持 adapter 分离，也可以把低秩增量合并回权重：

```text
W_merged = W + (alpha / r) B A
```

是否合并要根据工具链和实验目的决定。合并后要验证模型输出没有因保存/加载错误而改变。

## 7. 用 PEFT 时需要理解的边界

成熟库可以代替手写 LoRA 细节，但不能代替实验理解。至少要知道：

- 基础模型是什么。
- 适配器插入了哪些模块。
- 哪些参数可训练。
- checkpoint 如何保存和加载。
- 推理时是否加载了同一个基础模型和 adapter。

## 8. 最小自测

1. LoRA 更新和全量更新的参数量差别在哪里？
2. `r` 变大可能带来什么变化？
3. 为什么 `target_modules` 写错会导致实验无效或无法训练？
4. 你会用什么统计证明基础模型被冻结？
5. 保存 adapter 时为什么还需要记录基础模型标识？
