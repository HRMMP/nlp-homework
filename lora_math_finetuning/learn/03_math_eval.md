# 03. 数学任务、答案抽取与评估

## 1. 先定义数据对象

每道数学题至少要明确：

```text
question: 题目文本
answer:   参考答案
solution: 可选的参考解答或推理过程
```

如果数据集还包含题目类型、选项或元信息，也要说明它们是否进入 prompt。不要在没有确认字段含义时，把任意一个数字字段当作最终答案。

## 2. 数据划分和泄漏

- **训练集**：用于更新 LoRA 参数。
- **验证集**：用于选择 checkpoint、比较配置或早停。
- **测试集**：训练和调参结束后进行最终评估。

题目重复、同源改写、把测试答案写进 prompt，都会造成泄漏。应检查数据集划分方式，并记录去重或过滤规则。测试集上的每一项规则调整都应谨慎记录，否则 Accuracy 可能不再代表独立测试表现。

## 3. 答案抽取

生成结果可能包含解释、公式、单位和多个数字。抽取函数必须有明确规则，例如：

1. 优先查找约定的最终答案标记。
2. 若没有标记，按数据集允许的格式解析最后一个候选答案。
3. 解析失败时返回“无法抽取”，不能静默猜答案。

规则必须适用于真实输出，并保存抽取前的原始生成文本。不要只保存抽取后的数字，否则无法判断错误来自模型还是解析器。

## 4. 答案归一化

比较前可以做有限、可解释的归一化，例如：

- 去除首尾空白。
- 统一大小写（仅适用于文本答案）。
- 统一明确规定的逗号或空格格式。
- 将可安全解析的数字转换为统一表示。

分数、负数、百分数、单位、表达式和浮点精度都可能产生歧义。不能为了提高分数而随意删除符号或使用过宽松的字符串替换。归一化规则应写成测试，并在报告中说明。

## 5. Accuracy

如果测试集有 `N` 道题，判对题数为 `C`：

```text
Accuracy = C / N
```

每道题都应产生一个可审计的记录：

```json
{
  "question_id": "...",
  "reference_answer": "...",
  "generation": "...",
  "extracted_answer": "...",
  "correct": false,
  "error_reason": "extraction_failed"
}
```

`error_reason` 可以帮助区分：模型算错、格式不符合要求、答案抽取失败、归一化失败或数据异常。

## 6. 基线和对照

课程要求至少需要理解一个合理对照，例如未微调基础模型。对照应使用相同的测试集、prompt、生成参数、答案抽取和判分规则；否则分数差异无法归因于 LoRA。

正式结果表至少记录：

- 基础模型。
- 是否加载 LoRA。
- prompt 版本。
- 解码参数。
- 测试样本数。
- 判对数和 Accuracy。
- 答案抽取失败数。

## 7. LoRA 数学实验的最小验证清单

- [ ] 训练前能成功加载基础模型和 tokenizer。
- [ ] 一条样本的 prompt、labels 和忽略位置符合预期。
- [ ] 能打印总参数和可训练参数数量。
- [ ] 小数据 smoke test 能完成前向、反向和保存/加载 adapter。
- [ ] 推理脚本能保存原始生成文本。
- [ ] 答案抽取器有正常、负数、分数、无答案等测试。
- [ ] 评估脚本可以从预测文件独立重算 Accuracy。

## 8. 最小自测

1. 为什么必须保存原始 generation，而不只是保存抽取答案？
2. 测试集上发现抽取规则不适用时，应该如何处理实验记录？
3. 为什么基线和 LoRA 模型必须共享评估规则？
4. 如何区分“模型答错”和“解析器抽错”？
5. 哪些 prompt 或数据处理行为可能导致训练/测试泄漏？
